# 0047. GPU を使えないときと、アプリのフォルダの DLL が読めないときは、原因と次の行動を言う文を出す

状態: 採用

## 背景

使う人から見た問題は、たとえば次のとおり。

- 友人が、NVIDIA の GPU が無い PC で「インデックス作成を開始」を押す。画面に出るのは「インデックス作成を準備できませんでした: [ErrorCode:Fail] N:\_work\1\s\onnxruntime\core\providers\cuda\cuda_execution_provider_info.cc:167 … Failed to parse provider option "device_id": CUDA failure 801: (null) ; GPU=-1 ; hostname=… ; expr=cudaGetDeviceCount(&num_devices);」という、ONNX Runtime(0011)の英語の文である。GPU が無いことが原因だとは、読み取れない。サイドバーの 1 行では、「[ErrorCode:F…」で切れて見える。
- 展開した zip から、VC++ のランタイム(0044)の DLL が消えた(あるいは壊れた)。状態バーには「起動できませんでした: The type initializer for 'Microsoft.ML.OnnxRuntime.NativeMethods' threw an exception.」とだけ出る。原因の DLL の名前は、内側の例外にしか無い。
- 同じとき、VLM(画像から文字・説明文・タグを作る AI モデル。0018)の llama-server(0017)は、何も出力せずに終了コード -1073741515(16 進で 0xC0000135。Windows が、必要な DLL を見つけられなかったときの終了コード)で終わる。画面には「VLM の処理プログラム (llama-server) が起動中に終了しました(終了コード -1073741515)。直近のログ:」と、中身の無いログの末尾が出る。10 進の負数は、調べる手がかりにならない。

さらに、画面は長い文を省略記号で切る。状態バーの左の列は、最も狭い窓(幅 1042)で約 500 ピクセル、左パネルの補足の 1 行は約 264 ピクセルしかない。すべきことが文の終わりにあると、切れて見えなくなる。

どれも、利用者が直せる原因(ドライバの確認・zip の展開し直し)なのに、画面は何をすればよいかを言わない。

もう 1 つ、見落とせない場面がある。llama-server は、CUDA を初期化できないと、落ちずに CPU で動き続ける(下の表)。8B のモデルを CPU で回すと、実用にならない遅さで、利用者は「遅い」としか気づけない。画像側の ONNX Runtime は、GPU に載らないノードがあれば失敗にしている(0011)ので、揃っていない。

## 決定

次の 3 つの失敗を、原因と次の行動を言う、平らな文にする。見分けは Core で行い、文も Core が作る。画面は、既存の言い換え(`UiText.Plain`。0038)を通すだけで、文を変えない。

| 場面 | 見分け | 文(頭は、今までどおり「{段階}のインデックスを準備できませんでした: 」「起動できませんでした: 」) |
|---|---|---|
| CUDA を使えない(特徴ベクトル検索のインデックス作成) | ONNX Runtime の例外のメッセージに、失敗した式 `expr=cudaGetDeviceCount` が入っている | NVIDIA の GPU を使えません。NVIDIA のドライバと GPU を確かめてください (CUDA を初期化できませんでした) |
| アプリのフォルダの DLL が読めない(ONNX Runtime) | 例外の連なりの中に `DllNotFoundException` がある(外側は `TypeInitializationException`) | アプリのファイルが足りないか、壊れています。zip を展開し直してください (onnxruntime.dll を読み込めませんでした。足りないファイル: …) |
| アプリのフォルダの DLL が読めない(llama-server) | 起動中の終了コードが 0xC0000135 | アプリのファイルが足りないか、壊れています。zip を展開し直してください (VLM の処理プログラムが必要な DLL を読めず、起動できませんでした。終了コード 0xC0000135。足りないファイル: …) |
| CUDA を使えない(llama-server) | 起動の出力に `ggml_cuda_init: failed to initialize CUDA` の行がある | CUDA を使えないときの文と同じ |

- **文の並びは、すべきことを先に、細部を括弧の後ろに。** 画面が切っても、すべきことが見えるように(下の根拠の表)。llama-server の名前は文に入れず、警告のログに残す(画面の言い換えが名前を「VLM の処理プログラム (llama-server)」に替えるとき、括弧が入れ子になるため)。
- **見分けるのは、本当にその場面だけ。** 似た失敗(モデルが読めない・CUDA の別の失敗・GPU のメモリ不足)は、元の例外のまま通す。GPU が無いのか、ドライバが古い・壊れているのかは、ここでは見分けられないので、文はどちらとも言い切らない。
- **「足りないファイル」は、フォルダに実際に無いと確かめられたものだけ**: GPU の実行に要る 12 個(`NativeSelfCheck.RequiredFiles`)と、同梱の VC++ の 5 つ(0044)。フォルダが分からない・全部ある、なら、その節は出さない。ONNX Runtime は、読めなかった依存の名前を出さない(外側の DLL の名前になる)ので、名前を言い当てる代わりに、この検査で挙げる。
- **元の例外は、内側の例外に残す**(CUDA の失敗番号・ONNX Runtime の元の文・スタック)。ログには、今までどおり全部出る。画面から消えるのは、型名・ソースのパス・ホスト名・CUDA の関数名だけである。
- 例外には `NativeFailureKind`(`GpuUnavailable`・`FilesMissing`)を持たせる。画面の文は文字列で渡る経路(準備の状態・止まった原因・起動の失敗・失敗の一覧)が多いので、型は Core の中の見分けと試験に使い、画面は文だけを読む。
- **llama-server が 0xC0000135 で終わったときは、ポート違いのやり直しをしない**(ポートの競合ではないので、3 回やり直しても同じ)。それ以外の早期終了は、今までどおり。
- **llama-server が CUDA を初期化できなかったときは、起動を失敗にする**(CPU では動かさない)。画像側の「CPU に落ちたら失敗」(0011)と揃える。

## 検討した案

- **`UiText.Plain` の正規表現で、ONNX Runtime の英語の文を書き換える**: 元の文の細部(失敗番号・DLL の名前)が画面の言い換えで失われ、Core の文の変更で黙って効かなくなる。見分けの条件(どの例外の、どの式か)を Core の試験で固定できない。採らない。
- **例外の型を公開して、画面が型で分岐する**: 状態は文字列で複数の経路を通る(準備の状態・止まった原因・起動の失敗・失敗の一覧・画像ごとの理由)。型を全部の経路に通すのは大きな変更で、今回の目的に見合わない。採らない。
- **「CUDA」を含む失敗は、全部「GPU を使えません」にする**: メモリ不足やドライバの不整合まで同じ文になり、直し方が違うのに、同じ案内を出す。広く拾いすぎる。採らない。
- **llama-server は、CPU で動かして、警告だけをログに出す**: 起動は成功するが、極端に遅く、利用者は理由を知らないまま待つ。画像側の方針(0011)と食い違う。採らない。実際には、特徴ベクトル検索のインデックス作成が先に動くので、この場面は、GPU が途中で使えなくなったときなど、まれである。
- **VC++ の DLL が足りないと確かめたら、アプリが自分で直す(再取得する)**: ネットワークに出るのは、モデルの取得のときだけという約束(README)に反する。採らない。

## 根拠

Windows サンドボックス(.NET・VC++・NVIDIA のドライバが無い Windows 11。ネットワークは切断)で、配布物を展開して確かめた。何を測るか: 各場面で、画面の文(UI Automation で読む)・ONNX Runtime のメッセージ・llama-server の終了コードと出力。手元のモデルを使うが、画像は作った画像で、手元のスクリーンショットは使っていない。

| 場面 | 起きたこと |
|---|---|
| CUDA が無い(ONNX Runtime) | 「開始」を押して 0.2 秒で失敗。ONNX Runtime の英語の文に `CUDA failure 801: (null)` と `expr=cudaGetDeviceCount(&num_devices);` |
| CUDA が無い(llama-server の `--list-devices`) | `ggml_cuda_init: failed to initialize CUDA: (null)`、`Available devices: (none)`。終了コードは 0 |
| CUDA が無い(アプリと同じ引数での llama-server の起動) | 終了せず、約 18 秒で `/health` が 200。出力の頭に `ggml_cuda_init: failed to initialize CUDA: (null)` と `warning: no usable GPU found, --gpu-layers option will be ignored` |
| VC++ の 5 つが無い(ONNX Runtime) | 起動の 5 秒後に状態バーへ `The type initializer for 'Microsoft.ML.OnnxRuntime.NativeMethods' threw an exception.`。ログの全文に `DllNotFoundException: Unable to load DLL 'onnxruntime' or one of its dependencies`。アプリは落ちない |
| VC++ の 5 つが無い(llama-server) | `--version`・`--list-devices` とも、何も出力せず、終了コード 0xC0000135 |
| 同じ Windows で、仮想 GPU を有効にした(ホストの NVIDIA の GPU が見える) | 「開始」で、特徴ベクトル検索のインデックス作成が通しで動き(作った画像 6 枚、約 9 秒)、続けて llama-server も起動した。VC++ も .NET も要らなかった |

画面の幅(最も狭い窓の状態バーの左の列と、左パネルの補足の 1 行)を、実際の部品とフォントで測った。何を測るか: 文の先頭の、すべきことの部分が、省略記号で切れずに収まる幅。

| 場所 | 列の幅(ピクセル) | 「すべきこと」の部分に要る幅(ピクセル) | 結果 |
|---|---|---|---|
| 状態バーの左の列(最小の窓。起動の失敗) | 約 501 | 約 471(「起動できませんでした: 」を含む) | 収まる(試験で固定) |
| 左パネルの補足の 1 行(準備の失敗)。頭の「…を準備できませんでした: 」を付けたとき | 約 264 | 頭だけで約 190(段階名なし)〜261(段階名つき)。理由の最初の文が、残りに入らない | 収まらない |
| 左パネルの補足の 1 行。頭を外して、理由から始めたとき | 約 264 | 最初の文「NVIDIA の GPU を使えません。」約 149、「アプリのファイルが足りないか、壊れています。」約 206 | 収まる(試験で固定)。すべきことの文は全部は入らない(約 523〜536)ので、ヒント(全文)で読む |

見分けの条件は、この表の場面だけから作った。GPU が見えるがドライバが古い、といった別の場面は、同じ `cudaGetDeviceCount` の失敗になるはずだが、確かめていない(文が言い切らないのは、そのため)。

## 結果

- CUDA を使えないときと、アプリのフォルダの DLL が読めないとき、画面は、原因の見当と次の行動を平らな文で言う。詳細は、ログと内側の例外に残る。
- 見分けの条件が、1 か所(`NativeFailure`)にまとまる。ONNX Runtime のセッションを作る 3 か所(画像の GPU・画像の CPU・テキストの CPU)は、同じ包みを通る。
- llama-server は、CUDA を初期化できないと、起動を失敗にする。CPU だけの PC では、テキスト検索のインデックス作成は動かない(特徴ベクトル検索が先に失敗するので、実際には、その手前で止まる)。
- 画面の文は、Core の文と同じ文字列を、App の試験が写している。Core の文を変えたら、App の試験(`NativeFailureWordsTests`・`NativeFailureVisibilityTests`)も変える。
- 左パネルのインデックスの欄の補足の 1 行は、失敗の理由では、頭の「…を準備できませんでした: 」「止まった原因: 」を外して、理由の文から始める。すぐ上の状態の行に「停止中 (失敗で止まりました)」が出るので、失敗したことは分かる。頭が付いた全文(段階の名前つき)は、ヒントに残る。この 1 行は、準備の失敗と止まった原因の両方に同じ扱いで、ほかの補足(準備中・スキャン中・ファイル名・飛ばした・モデル未取得)は変えない。
- 理由の最初の文は、1 行に収まる。2 つ目の文(すべきこと)は、行の幅に入りきらず、省略記号で切れる。全文はヒントで読む。行を折り返す案は、左パネルの高さを測る試験(`IndexSectionHeightTests`)に触れるので、採らない。
- 範囲外: SQLite・Skia のネイティブ DLL が無いときの起動の失敗は、この決定の対象でない(今は、一般の失敗の文のまま)。

## 見直す合図

ONNX Runtime や llama.cpp の更新で、GPU が無いときのメッセージ(`expr=cudaGetDeviceCount`・`ggml_cuda_init: failed to initialize CUDA`)が変わったとき。CPU だけの PC に対応するとき(llama-server を CPU で動かす決定をやり直す)。別の原因(ドライバが古い・GPU のメモリ不足)で、利用者が同じ文を見て迷う報告が出たとき。
