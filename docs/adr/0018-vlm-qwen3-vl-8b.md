# 0018. 画像から文字・説明文・タグを作る VLM には、Qwen3-VL-8B-Instruct(Q4_K_M の量子化)を使う

状態: 採用

## 背景

VLM(画像と文章を扱える AI モデル。ここでは、画像から、写っている文字・説明文・タグを作る。0017)に、画面の文字の書き起こし(OCR。0021)・説明文・タグを作らせる。使う人から見た問題は、たとえば、セリフで探したいときに、書き起こしが 1 文字違うだけで検索に当たらなくなることである。選ぶ条件は次のとおり。

- 対象環境は VRAM 8GB 以上・RAM 16GB 以上(リポジトリ直下の AGENTS.md)。VLM の分は、デスクトップが使う分と余裕を引いて、プロセス単位で 6.5GiB(6,656MiB)に収める。
- 日本語のゲーム画面の文字を、検索に使える精度で読めること。検索は文字 bigram の全文検索(0029)なので、4〜6 文字のフレーズは 1 文字の誤りで外れる。
- 文字のない画像に、実在しない文を作らないこと。露出の多い絵でも、拒否や説教文でなく、JSON と説明文を返すこと。
- 画像 1 枚の処理は遅くてもよい(精度を優先する。裏で回し続ける)。

## 決定

VLM は、Qwen3-VL-8B-Instruct の Q4_K_M を使う。Q4_K_M は量子化の方式で、モデルの重みを約 4 ビットで持ち、メモリを減らす(Q8_0 は 8 ビット)。

- 重みは、公式の GGUF(llama.cpp 用のモデルのファイル形式)`Qwen/Qwen3-VL-8B-Instruct-GGUF` のリビジョン `f982a07559d4a2f6c8744d840bf6fccab30eea96` の `Qwen3VL-8B-Instruct-Q4_K_M.gguf`(5,027,784,800 バイト)。画像エンコーダ(mmproj。画像を VLM が読める形にする部品のファイル)は同じリポジトリの `mmproj-Qwen3VL-8B-Instruct-F16.gguf`(1,159,029,824 バイト)。mmproj は CPU に置く(0019)。
- Instruct 版を使い、思考(thinking)は使わない。
- temperature は 0。
- 定数は `src/Ohanami.Core/Models/VlmCatalog.cs` にある。値を変えると、新しい model_id になり、全件が要再作成(作り直しが要る状態)になる(0006)。

## 検討した案

評価した候補は 6 つである。表の CER(文字誤り率)は、正解の文字列との編集距離(文字の置き換え・抜け・余りの数)を、正解の文字数で割った値で、小さいほどよい。再現率(文字 bigram の再現率)は、正解の中の「隣り合う 2 文字の組」のうち、出力にも出てきた割合で、大きいほどよい。日本語の全文検索は 2 文字の組で引く(0029)ので、再現率が、検索で当たる割合に近い。表の「足切り」は、1 つでも落ちたら不採用になる条件、「合格線」は、採用の最低の基準で、どちらも「根拠」に書く。「素直なセリフの層」は、フォントが素直なセリフ画面 12 枚、「難しい画像の層」は、手書き/縦書き・小さい UI・装飾・大判の 14 枚である(評価の画像の分け方は「根拠」に書く)。

| 候補 | 結果 |
|---|---|
| Qwen3-VL-8B-Instruct Q4_K_M(採用) | 足切りと合格線をすべて通った |
| Qwen3.5-9B Q4_K_M | 合格線に届かない。素直なセリフの層の CER が 12.55%。順位を決める難しい画像の層の再現率が、採用案より約 9pt 低い |
| Qwen3-VL-8B Q8_0 | 良くならず、遅く、ループも出た。採らない |
| Qwen3-VL-4B Q8_0 | 合格線に届かない。文字のない画像に、画面にない副題を書き足した(でっち上げ) |
| Qwen3.5-4B Q8_0 | 33 枚のうち 3 枚が同じ語の繰り返しのループになり、JSON の足切りに落ちた |
| Qwen3-VL-30B-A3B Q4_K_M(MoE。一部の専門家だけを動かす構造のモデルで、その部分をすべて CPU に置く) | 難しい画像の層だけ約 2.4pt 上だが、素直なセリフの層が不合格で、RAM が 19.5GB 要る。対象環境に載らない |

比べ方の決まり: 比較に第三者の量子化を混ぜない(imatrix(量子化の精度を保つための重要度の情報)の有無やテンプレートの違いが結果に混ざるため)。Qwen3.5 には公式の GGUF が無いので、素の Q4_K_M を使い、UD 系(層ごとに量子化の度合いを変える方式)の量子化は使わない。mmproj は、手に入るうちで最も精度の高いもの(F32 があれば F32、なければ F16)を使う。Qwen3.5 は、`chat_template_kwargs: {"enable_thinking": false}` を明示しないと、llama-server b12110 が思考をオンにする。

## 根拠

### 採否の線(測る前に決めた)

足切り(1 つでも落ちたら不採用):

- JSON が全画像でパースできる。
- 文字のない画像の層で、実在しない文を作らない(画面に実在する短いラベル程度は可)。
- 露出の多い画像の層で、拒否や説教文でなく、JSON と使える説明文が返る。
- llama-server プロセスの VRAM のピークが 6,656MiB(6.5GiB)以下、RAM(ワーキングセット)が 6GB 以下。
- 1 万枚が 1 か月以内に終わる(1 枚 250 秒以下。異常な構成を弾くための基準)。

合格線: 素直なセリフの層で、CER ≤ 3% かつ文字 bigram の再現率 ≥ 95%。順位は、合格した候補を、難しい画像の層の再現率で並べる。ノイズの目安は CER 1pt、再現率 2pt で、同点なら構成が単純なほうを採る(全部 GPU に載る > 一部を CPU に逃がす > MoE の expert を CPU に置く)。

### 評価の画像と採点

開発者の手元の約 1,000 枚から層別に選んだ 33 枚で測った。データは公開していない。層は、素直なセリフ 12(「素直」層)・手書き/縦書き 4・小さい UI 4・装飾 3・大判 3(以上 14 枚が「難しい」層)・文字なし 4・露出が多い絵 3。

参照の書き起こし(正解の文字列)は、採用した構成(候補 1)の出力を下書きにして、人が画像を見ながら直した。下書きに偏るので、候補 1 に有利である。そこで、候補 1 以外の 2 モデルが、そろって参照と違う読みをしている箇所(9 枚・約 11 か所)を機械的に抜き出し、画像で確かめて参照を直した。直す前は、候補 1 の素直な層が、再現率 99.58%・CER 0.27% と、実際より良く見えていた。直した後の数字が、下の表である。CER は並び順の違いを誤りとして数えるので、候補どうしの比較には、並び順の影響を受けにくい bigram の再現率を主に使う。

ループ(同じ語を繰り返して止まらなくなること。0023)して JSON が壊れた画像は、「出力が空だった」として採点に含める(除外すると、失敗したモデルが有利になる)。

### 採点の結果

CER(文字誤り率)は、正解の文字列との編集距離(文字の置き換え・抜け・余りの数)を、正解の文字数で割った値で、小さいほどよい。文字 bigram の再現率は、正解の中の「隣り合う 2 文字の組」のうち、出力にも出てきた割合で、大きいほどよい。日本語の全文検索は 2 文字の組で引く(0029)ので、再現率が、検索で当たる割合に近い。

| 候補・設定 | 素直 CER | 素直 再現率 | 難しい CER | 難しい 再現率 | 手書き/縦書き 再現率 | 小さい UI 再現率 |
|---|---|---|---|---|---|---|
| 8B Q4_K_M(既定) | 2.80% | 96.88% | 8.86% | 91.50% | 81.25% | 95.38% |
| 8B Q4_K_M(`--image-min-tokens 1024`) | 4.94% | 97.01% | 16.67% | 84.19% | 87.50% | 75.66% |
| Qwen3.5-9B Q4_K_M(既定) | 12.55% | 95.12% | 22.18% | 82.75% | 85.71% | 69.09% |
| Qwen3.5-9B Q4_K_M(1024) | 22.56% | 82.90% | 17.29% | 86.00% | 86.61% | 75.94% |
| Qwen3-VL-4B Q8_0(mmproj を GPU) | 12.15% | 87.38% | 18.53% | 86.94% | 62.80% | 91.33% |
| Qwen3-VL-4B Q8_0(mmproj を CPU) | 9.88% | 89.82% | 18.59% | 86.81% | 62.80% | 91.05% |
| Qwen3.5-4B Q8_0(mmproj を CPU) | 16.42% | 92.81% | 36.93% | 65.94% | 29.17% | 60.14% |
| 8B Q8_0(`-ngl 24`) | — | 90.64%(ループした 1 枚を含む。除くと 96.39%) | — | 92.00% | — | — |
| 30B-A3B Q4_K_M(`-cmoe`: MoE の専門家を CPU に置く指定) | 14.95% | 92.67% | — | 93.88% | — | — |

画像トークンの最小値(`--image-min-tokens`)は 0019 で扱う。

読み方:

- 8B Q4_K_M は、足切りをすべて通り、合格線(CER ≤ 3%、再現率 ≥ 95%)を通った。ただし CER は 2.80% で、線にぎりぎりである。
- Qwen3.5-9B は、素直な層の再現率(95.12%)は 8B との差がノイズの範囲だが、CER が合格線を通らない。CER の並び順の偏りを割り引いて仮に合格としても、順位を決める難しい層の再現率が 8B(91.50%)に 8.75pt 離される。どちらに転んでも、世代の比較は Qwen3-VL-8B の勝ち。
- 8B Q8_0 は良くならなかった(難しい層の +0.5pt(パーセントポイント。割合の差)はノイズの範囲)。1 枚の中央値は 20.8 秒(Q4_K_M は 12.9 秒)で、1 枚が「ステージの」の繰り返しのループになった(Q4_K_M ではこの画像はループしない)。
- 4B は、どちらも合格線を通らない。Qwen3-VL-4B Q8_0 は、画面にない副題を書き足した(でっち上げの検査で不合格)。mmproj を GPU に置いても CPU に置いても、精度の差はノイズの範囲だった。
- 30B-A3B は、難しい層だけ約 2.4pt 上(ノイズの目安 2pt を超える)。素直な層の CER が 14.95% で不合格、RAM が 19.5GB(プライベートは 22GB)で、RAM 16GB の機械に載らない。

### VRAM と速度

足切りは、llama-server プロセスのピークで見る(0019)。

| 構成 | VRAM(プロセス分のピーク) |
|---|---|
| 8B Q4_K_M、mmproj を GPU | 6,952MiB(足切り超) |
| 8B Q4_K_M、mmproj を CPU | 6,199MiB |
| Qwen3.5-9B Q4_K_M、mmproj を CPU | 5,473MiB |
| Qwen3-VL-4B Q8_0、mmproj を GPU | 6,828MiB(足切り超) |
| 8B Q8_0、`-ngl 24` | 6,505MiB |
| 30B-A3B、expert を CPU | 2,160MiB(RAM が 19.5GB) |

8B Q4_K_M の 1 枚の中央値は約 13 秒で、1 万枚で約 36 時間である。

### 1030 枚の通し

採用した構成で、実際の手元のライブラリ 1030 枚を通した。HTTP 200 が 1030/1030、パースに成功 1014、失敗 16(すべて `finish_reason=length` のループ)。ループへの備え(0023)を入れたあとの通しは、最終的な失敗 0、所要 3.34 時間(足切りの線は 4.5 時間)で、VRAM のピークはプロセス別で 6,058MiB だった。1 回目で成功した 1014 枚の出力は、評価のときの出力と、書き起こし・説明文・タグとも完全に一致した。

## 結果

- 手書き/縦書きの再現率は 81% と弱い(漫画風・縦書きのセリフは、検索で取りこぼしやすい)。
- 説明文には、事実の誤りがある(動物の種類を取り違える、見えていない姿勢を補う、など)。採点の対象外だが、検索に影響する。
- 約 12〜13 秒/枚、1 万枚で約 36 時間なので、初回の処理は日単位の裏の作業になる。VLM の全件の再処理も同じである。
- 約 6GiB の VRAM を握る(0019)ので、特徴ベクトルの作成と同時には動かせない(0027)。
- 量子化(Q8_0)を上げても、改善しなかった。

## 見直す合図

- 新しいモデルが、同じ足切り・合格線・評価の画像で、素直な層と難しい層の両方で上回ったとき(同じ手順で測り直す)。
- 対象環境の VRAM・RAM の下限を上げるとき。大型のモデルが載る。
