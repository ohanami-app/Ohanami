# 0046. ビルドとテストに要る、Git に入れていないファイルは、手で動かすスクリプトで一次の配布元から取り、SHA-256 を確かめて置く

状態: 採用

## 背景

使う人から見た問題は、たとえば次のとおり。ソースを公開したあと、初めて clone した人が、`dotnet build` を打つ。すると、「CUDA / cuDNN の DLL が無い: …\runtime\cudnn\9.28.0.42_cuda13\cudnn64_9.dll」と出て止まる。どこから、どの版を取ればよいのか、画面には書いていない。文書に手順だけを書いても、版を 1 つ間違えた(CUDA 12 用の cuDNN を取った、など)ファイルが、静かに置かれて、動かない原因が分からなくなる。通常のテストも、トークナイザの 1 ファイル(`tokenizer.json`)が無ければ失敗する。

ビルドとテストが要るファイルのうち、Git に入っていないものは、次のとおり(ライセンスと大きさのため。0016・0017・0042・0045)。

- `runtime/llama.cpp/b12110/`: llama.cpp の本体と、CUDA の DLL(`cudart`・`cublas`・`cublasLt`)。llama.cpp のリリースの zip 2 つにある。
- `runtime/cudnn/9.28.0.42_cuda13/`: cuDNN の DLL 7 個(0016)。NVIDIA の配布元の zip(約 1.3GB)にある。
- `runtime/vcruntime/14.44.35211_x64/`: VC++ ランタイムの DLL 5 個(0044)。Visual Studio の再配布のフォルダにある。単体の配布元は無い。
- `models/ViT-SO400M-16-SigLIP2-384__ohanami/textual/tokenizer.json`: 通常のテストが要る(約 34MB)。変換の入力(`timm/ViT-SO400M-16-SigLIP2-384` のコミット `fec784dabb3081a5f101fc74eefaf9d1ed08237b`)の同名のファイルと、バイトまで同じである。

製品がネットワークに出るのは、利用者が「ダウンロード」を押したときの、モデルの取得だけである(0043。見張りのテストがある)。この作業は、製品ではない。開発者が、手で、1 度だけ動かす。

## 決定

**`tools/runtime/Get-Runtime.ps1`(PowerShell)を、手で動かして、上の 4 つを取って置く。取る先は、一次の配布元(GitHub の ggml-org/llama.cpp のリリース、NVIDIA の cuDNN の配布元、Hugging Face の timm のリポジトリ)だけ。置く前に、SHA-256 を確かめ、1 つでも違えば止まる。**

- **zip の SHA-256**: スクリプトの定数。llama.cpp の 2 つの zip は、GitHub のリリースが公開する digest と同じ値であることを確かめて、定数にした。cuDNN の zip は、NVIDIA の配布元の `redistrib_9.28.0.json` の値と同じことを、最初に取ったときに確かめてある(`runtime/cudnn/` の `SOURCE.txt` の記録)。
- **置くファイルの SHA-256**: `tools/release/allowed-files.tsv`(0042)の値。配布物と同じ表を使うので、開発のビルドと配布物が、同じバイト列を使う。
- **製品が使うファイルだけを置く**: 表の行(llama.cpp 23 個、CUDA 3 個、cuDNN 7 個)を、zip の名前で取り出す。zip の中の名前で、置き場所を決めない(zip の細工で、別の場所に書かれないように)。llama.cpp の zip にある、ほかの exe や、cuDNN の使わない DLL は、置かない。
- **VC++ ランタイムは取らない**: Visual Studio 2022 / Build Tools の、再配布のフォルダ(`VC\Redist\MSVC\<版>\x64\Microsoft.VC143.CRT`)を、`vswhere.exe` と既定の場所から探し、表と SHA-256 が同じ 5 個を写す。見つからなければ、取り方を案内して、終了コード 1 で止まる。
- **置き場の扱い**: 同じ名前で中身の違うファイルがあれば止まる(`-Force` で上書き)。そろっていれば、何も取らない。取ったあと、置く前に、取り出したファイルの SHA-256 を確かめる(確かめたあとにだけ、置く)。
- **`tokenizer.json`**: SHA-256 の定数は、`models/MANIFEST.tsv`(Git に入っている)の値と同じことを、スクリプトが確かめる。テストも、同じ値で確かめる。
- **見張り**: `GetRuntimeScriptTests`(Core.Tests)が、スクリプトの置き場の名前が `build/*.targets` と同じであること、表の出どころの名前が合っていること、`tokenizer.json` の定数が `MANIFEST.tsv` と同じであること、スクリプトの URL が上の 3 つの配布元だけであること(TLS)を、スクリプトを動かさずに読んで確かめる。

## 検討した案

| 案 | 採らなかった理由 |
|---|---|
| 手順を文書に書くだけにする | 版の取り違えや、壊れたファイルが、静かに置かれる。ビルドが止まっても、原因が分からない |
| VC++ ランタイムも、Microsoft の再頒布パッケージ(`vc_redist.x64.exe`)から取る | 配布元は、最新の版だけを配る。表の SHA-256(14.44.35211.0)と一致しなくなる。インストーラは、DLL を System32 に入れるだけで、`runtime/` の形にならない |
| 取りながら、ハッシュを計算する | 中断のたびに、状態を持ち越す。取り終わったあとの検証(数 GB で数秒)で足りる(0043 と同じ) |
| 途中からの再開(`Range`)を作る | 取る量は約 1.9GB で、再開が要る大きさではない。壊れた途中のファイルを、再開で足す危険のほうが大きい。止まったら、次は取り直す |
| zip を、リポジトリや Releases に置く | 再配布のファイルを、こちらが持つことになる(NVIDIA の規約の再配布の条件。0045)。一次の配布元から取れば足りる |

## 根拠

- 実際に、空の場所(リポジトリの外の一時フォルダ)に取って置いて、手元の `runtime/` と比べた。置いた 38 ファイル(llama.cpp 23、CUDA 3、cuDNN 7、VC++ 5)は、手元の `runtime/` の同じパスのファイルと、バイト単位で同一だった。`tokenizer.json` も同一(SHA-256 `220c63d4…779b04`)。置いた `runtime/` は約 1.2GB(zip は 3 つで 1,858,590,206 バイト)。
- 確かめた失敗: 置き場のファイルが 1 バイト違うと、`-Force` なしで止まり、`-Force` で戻る。VC++ の表の値を違えると、見つかった再配布のフォルダ(と、その版)を示して、終了コード 1 で止まる。zip の中に、置くファイルが無いと、その名前を示して止まる(cuDNN の zip の中の置き場が、想定の `bin/` でなく `bin/x64/` だったとき、実際にこれで止まった)。
- 確かめていない: 取得元が、`Range` や `User-Agent` などに、将来どう応じるか。回線が途中で切れた場合の動き(`curl` の再試行は 3 回。続きから取らず、zip を取り直す)。cuDNN の zip の SHA-256 が、NVIDIA の配布元で将来差し替わったとき(スクリプトは、定数と違えば、ファイルを消して止まる)。

## 結果

- clone した人は、`pwsh tools/runtime/Get-Runtime.ps1` の 1 回で、ビルドと通常のテストに要るファイルがそろう(手順は `tests/README.md`)。
- 製品のネットワークの約束(0043)は変わらない。このスクリプトは製品の外にあり、`NetworkBoundaryGuardTests` の対象ではない。代わりに、`GetRuntimeScriptTests` が、取る先を 3 つの配布元に限る。
- 同梱物の版(llama.cpp・cuDNN)を替えるときは、スクリプトの URL・zip の SHA-256・置き場の名前と、`build/*.targets`・許可の表を、同じ変更で直す(置き場の名前と表の食い違いは、テストが見張る。zip の SHA-256 は、取ってみないと分からない)。

## 見直す合図

- llama.cpp・cuDNN・VC++ ランタイムの版を替えるとき。
- 取得元(GitHub のリリース、NVIDIA の配布元、Hugging Face)の URL や応答が変わって、取れなくなったとき。
- 取る量が増えて、途中からの再開が要るようになったとき。
- VC++ の再配布のフォルダが、Visual Studio の新しい版で、探している場所に無くなったとき。
