# 0045. 本体は MIT License で公開し、第三者の表示とライセンスの全文を、リポジトリと配布の zip に同じ形で置く

状態: 採用

## 背景

使う人から見た問題は、たとえば次のとおり。

- Ohanami の zip を展開した人が、フォルダの中の `cudnn_ops64_9.dll` を見つけて、「Ohanami は MIT だから、これも自由に取り出して、自分のアプリに入れて配ってよい」と考える。しかし、この DLL は NVIDIA の物で、NVIDIA の規約は、単体で配ることを認めない。同じことが、Microsoft の `vcruntime140.dll` にも起きる。
- 逆に、作者が、MIT・Apache-2.0 などの第三者のソフトウェアを、元の著作権表示とライセンスの文を付けずに配ると、それらのライセンスに反する(どれも、配るときに、著作権表示とライセンス文を付けることを求める)。

配布物(0042)の約 470 ファイルのうち、MIT・Apache-2.0・BSD・パブリックドメインのものが大半で、NVIDIA の規約で配る DLL が 10 個、Microsoft の使用許諾条件で配る DLL が 5 個ある。Ohanami 本体のコードも、次の 2 つに、第三者のコードの写しを含む。

- 画像のリサイズ: Python の画像ライブラリ Pillow の `Resample.c` を C# に写した(`PillowResample`)。
- BPE(語を、語彙の中の断片に分けるトークナイザの処理): Rust の tokenizers の `merge_word`・`Word::merge_all` を C# に写した(`BpeWord`)。

モデルのファイルは、zip に入らず、利用者が取る(0043)。SigLIP2 の ONNX は、Google の重みを、この作者が変換して Hugging Face に置く(0012)ので、元の作者の表示が要る。

## 決定

**Ohanami 本体のコードは MIT License で公開する。著作権者は `Ohanami contributors`(作品の名前)、年は 2026。第三者の表示は、`THIRD-PARTY-NOTICES.md` と `licenses/` に書く。この 3 つ(`LICENSE`・`THIRD-PARTY-NOTICES.md`・`licenses/`)は、リポジトリの直下と、配布の zip の直下に、同じパスで置く。**

- **一覧**(`THIRD-PARTY-NOTICES.md`): zip に入る第三者のソフトウェアごとに、名前・版・ライセンス名・著作権者・入手元・ライセンス全文のファイルを書く。llama.cpp のソースに入っている部品(cpp-httplib など)も、ビルド済みの配布物に入っているかを確かめていないので、念のため載せる。
- **全文**(`licenses/`): NuGet のパッケージに入っている `LICENSE`・`ThirdPartyNotices` は、そのまま写す。パッケージに全文のないもの(SQLitePCLRaw は Apache License 2.0 の標準の全文、Microsoft.Data.Sqlite は同じ作者のリポジトリの `LICENSE.txt`)は、代わりのものを付けて、その旨を一覧に書く。NVIDIA の 2 つの規約と、Visual Studio 2022 Community の使用許諾条件も、全文を付ける(URL だけにしない。配布物だけで条件が読めるように)。
- **NVIDIA の DLL**(CUDA の `cudart`・`cublas`・`cublasLt`、cuDNN の 7 個): MIT の対象ではないと書く。NVIDIA の規約に従い、改変せずに入れてあると書く。規約が求める次の禁止事項も、書く: Ohanami からだけ使う・単体で配らない / 逆アセンブル・逆コンパイルをしない / 表示を消さない / オープンソースのライセンスの対象にしない / NVIDIA の推薦を示さない / cuDNN は NVIDIA の GPU のある PC のため。
- **Microsoft の VC++ ランタイム**(0044): 同梱を続ける。使用許諾条件の配布の要件(2)(配る人と利用者に、配る DLL を同程度に保護する条件へ同意させる)のため、同意を求める文を書く: 単体で配らない・逆コンパイルしない・表示を消さない・商標を使わない・無保証。この文は、`THIRD-PARTY-NOTICES.md` と README で、同じ文を使う。
- **写したコード**: Pillow と tokenizers の表示(著作権者・ライセンス名・全文の場所)を、`THIRD-PARTY-NOTICES.md` と、写した部分があるソースの冒頭(`ImagePreprocessing.cs`・`Siglip2Tokenizer.cs`)のコメントに書く。「動作に従って書き直した」とは言わず、「写した」と書く(コードのコメントがそう言っており、どちらでも守るべき表示が足りる側に合わせる)。
- **モデル**: Qwen3-VL(Apache-2.0)と SigLIP2 を、一覧に載せる(zip に入らないことと、入手元も書く)。SigLIP2 は、Apache-2.0 と CC BY 4.0 の帰属を、両方書く(作者・ライセンス名・リンク・「ONNX に変換した」という変更の表示)。Hugging Face のリポジトリの README(モデルカード)・LICENSE・NOTICE も、同じ内容で、英語で書く。
- **zip に入れる仕組み**: `build/OhanamiPublish.targets` が、publish の出力に、この 3 つをリポジトリの同じパスで入れる(開発のビルドには入れない)。許可の表(0042)に、出どころ `repository` の行として載せる(SHA-256 は書かない)。`Publish-Release.ps1` は、出力の文書が、リポジトリの同じパスのファイルと、バイト単位で同一であることを確かめる。

## 検討した案

| 案 | 採らなかった理由 |
|---|---|
| NVIDIA の DLL の節を短く(「NVIDIA の物で、MIT は及ばない」だけ)にする | 規約が求める禁止事項を、DLL を受け取る人に伝えるのが、この節の目的である。禁止事項まで書けば、取り出して配る誤りを防げる |
| VC++ のランタイムを同梱せず、利用者に Microsoft の再頒布パッケージを入れてもらう | 使用許諾条件の要件(2)の問題は消えるが、zip を展開してすぐ動く、という 0044 の決定を捨てる |
| ライセンス全文を、URL だけで指す | 配布物だけでは条件が読めない。リンク先が変わる・消えることもある |
| ライセンスの文をそのまま写すのでなく、要約する | 要約は誤りうる。NuGet が付けている文は、そのまま写す |
| 写したコードを「書き直したもの」とし、表示を省く | 元のコードの構造を、手順まで写している。表示を付ける義務が軽くなるかは法的な判断になるので、足りる側(「写した」)に合わせる |
| SigLIP2 の表示を、Hugging Face の札(Apache-2.0)だけにする | 作者の説明(big_vision の `README_siglip2.md`)は、ソフトウェアを Apache 2.0、そのほかの素材を CC BY 4.0 としており、重みがどちらに当たるかは、公開された資料から決められない。厳しい側(帰属を求める CC BY 4.0)に合わせれば、どちらでも足りる |
| 著作権者を、最初の作者の名前にする | 貢献者が加わるたびに、書き方を変えることになる。作品の名前なら、誰が加わっても同じ書き方で済む |
| 許可の表に、文書の SHA-256 を書く | 文書を直すたびに表も直すことになる。リポジトリの同じパスのファイルとの同一を確かめれば足りる |

## 根拠

- NVIDIA と Microsoft の規約は、原文(CUDA Toolkit EULA・cuDNN Software License Agreement・Visual Studio 2022 Community の使用許諾条件)を読んで、再配布の要件を拾った。下の表は、どの要件を、どこで満たすかを示す。法的な解釈ではなく、条文を読んだもの。弁護士の確認はしていない。

  | 規約が求めること | 満たす場所 |
  |---|---|
  | 配る DLL を、アプリ(Ohanami)からだけ使う。単体で配らない(NVIDIA・Microsoft) | 本体のコードだけが DLL を使う。`THIRD-PARTY-NOTICES.md` に禁止を書く |
  | 逆アセンブル・逆コンパイルをしない。表示を消さない(NVIDIA・Microsoft) | 改変せずに入れる(許可の表の SHA-256 が見張る)。`THIRD-PARTY-NOTICES.md` に書く |
  | 配る条件が、規約と整合し、NVIDIA の知的財産を守る(NVIDIA)。配る人と利用者に、同程度に保護する条件へ同意させる(Microsoft) | `THIRD-PARTY-NOTICES.md`(と README)に書く |
  | オープンソースのライセンスの対象にしない(NVIDIA・Microsoft) | 本体の MIT は、本体のコードだけに及ぶ、と書く |
  | 推薦・商標を示さない(NVIDIA・Microsoft) | 書く。アプリの名前に使っていない |
  | 配る DLL が、規約の「再配布してよいもの」の一覧にある(NVIDIA の CUDA は付属書 A) | `cudart`・`cublas`・`cublasLt` は、付属書 A にある。cuDNN は、規約の補足が、実行時の DLL を再配布できるとしている |

- 一覧の版・ライセンス名・著作権者は、NuGet パッケージのメタデータ(nuspec)・パッケージ内のライセンスのファイル・DLL のファイルの情報・各プロジェクトのライセンス文から取った。llama.cpp と NVIDIA の DLL の版は、配布物にある DLL の情報と、公式の配布物の名前による。
- `DistributionLayoutTests` が、許可の表の `repository` の行が、リポジトリの 3 つの文書と過不足なく一致すること、一覧が `licenses/` のファイルをすべてリンクしていること、未決の印が残っていないこと、ソースの冒頭に表示があることを見張る。`Publish-Release.ps1` が、publish の出力の文書が、リポジトリのファイルと同一であることを見張る。

## 結果

- zip を展開した人は、直下の `LICENSE`・`THIRD-PARTY-NOTICES.md` から、同梱物の一覧と、それぞれのライセンスが読める。取り出して配ってはいけない DLL も分かる。
- 同梱物の版を替えたり、同梱物を増やしたりすると、許可の表との突き合わせ(0042)が失敗する。そのとき、`THIRD-PARTY-NOTICES.md` の版・ライセンスも、同じ変更で直す(許可の表と文書の食い違いは、機械では見張っていない)。
- 確かめていないこと: ビルド済みの llama.cpp に、一覧の vendor の部品が実際に入っているか。`ggml-cuda.dll` の中の、ほかの第三者のコードのライセンス。VC++ の条件への「同意」を、README に書くだけで足りるか(アプリの画面で見せる案もある。法的な判断)。
- Hugging Face のモデルカード・LICENSE・NOTICE は、リポジトリの外で作る(Hugging Face に置くのは、モデルのファイルと一緒に、人の手で行う)。公開リポジトリの URL が決まったら、モデルカードの変換の道具の参照先を書き足す。

## 見直す合図

- 同梱物(DLL・NuGet パッケージ・llama.cpp・.NET)の版を替えたとき、増やしたとき。
- NVIDIA・Microsoft の規約が改訂されたとき。再配布の要件を読み直す。
- VC++ の条件への同意の取り方を、画面に移すとき。
- 署名つきの配布(Microsoft Store など)にするとき(署名は 0049)。ストアの規約が、同梱物の扱いを変えうる。
