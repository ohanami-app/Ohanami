# 0034. 検索結果に「関連度が低い」画像を分けて出す仕組みは入れない

状態: 採用

## 背景

### 使う人から見た問題

特徴ベクトル検索(SigLIP2。画像と検索語を同じモデルでベクトルにして、近さで探す。0011)は、全画像に順位を付ける。たとえば「ねこ」と打つと、猫が写っている画像が上に来るが、猫と関係のない画像にも順位が付き、300 件まで並ぶ。当たりが 3 枚しか無くても、結果は 300 枚になる。

要件には、近さ(類似度)のしきい値を決め、それを下回る画像を「関連度が低い」として下に分けるか、結果から除く、と書かれている。しきい値は調整できるようにする、とも書かれている。

### 除くことの危うさ

除くと、しきい値が合わない検索では、目的の画像が画面から見えなくなる(下に区切る形と違い、スクロールしても出ない)。近さの値の尺度は、検索語の型(短い語・長い文・固有名詞)で動くと考えられ、評価に使った標本に無い型の検索語で全体の近さが低く出ると、特徴ベクトル検索だけで出ていた目的の画像が消える。そのため、入れる前の守りの規則を、結果を見る前に決めた。

## 決定

関連度が低い画像を分ける仕組みは入れない。結果から除く処理も、下に区切って出す処理も、しきい値の設定も作らない。特徴ベクトル検索は、全画像に順位を付けたまま、もう 1 つの検索(テキスト検索。VLM が作った OCR・説明文・タグと、手動タグの文字を、全文検索で探す)とまとめる(0033)。

## 検討した案

| 案 | 内容 |
|---|---|
| 一覧の下に区切って出す | しきい値は Core(検索と DB の本体)の定数にし、設定の画面は作らない |
| 結果から除く | 守りを 3 層で置く。検索の中でだけ「除いた N 件を表示する」で取り返せるようにする |
| 区切って出し、しきい値を設定の画面で変える | 設定の画面が増える |

3 案とも、「関連のある画像」と「関連の薄い画像」の近さの値に、分かれ目があることが前提である。分かれ目が無ければ、どの案も作らない。

## 根拠

分かれ目を、開発者の手元の約 1,000 枚と、その画像に対する検索語で測った。データは公開していない。使う用語は次のとおりである。

- **近さ(cosine)**: 検索語のベクトルと画像のベクトルの近さを表す値(正規化したベクトルの内積。理論上は −1〜1 で、大きいほど近い)。
- **precision@10 の当たり・外れ**: 検索語ごとの上位 10 枚について、利用者が目視で判定した結果。
- **known-item**: 「探したい 1 枚」と「そのとき打つ検索語」の組。

決め方は次のとおり(結果を見る前に決めた)。

- 守る集合 P: (a) 今の上位 300 件(画面に出る範囲)に入っている known-item の目的の画像、(b) 判定で当たりの画像のうち、特徴ベクトル検索の上位 10 件に入っていたもの。**P が 1 件でも除かれる線は採らない。**
- 余裕: 線は、P の最小の近さから 0.01 以上下に置き、分布の空いた谷に置く(埋め込みは GPU で小さく揺れ、実際のライブラリは評価の標本と違うため)。
- 効き目の下限: 判定で外れの画像のうち、特徴ベクトル検索の上位 10 件に入っていたもの(集合 M)の、20% 以上を除けなければ、除く判定は入れない。めったに働かない除外は、働いたときだけ驚かせるので、無いより悪い。
- 線は、近さの絶対値を試し、分かれなければ、1 位との近さの差を試し、それでも分かれなければ、入れない。

結果。

| 項目 | 値 |
|---|---|
| 守る集合 P | 168 組((a) 51・(b) 134・重なり 17) |
| 効き目の母集団 M | 256 組 |
| P の最小の近さ | 0.0239 |
| 線(P の最小から 0.01 下) | 0.0139 以下 |
| M の最小の近さ | 0.0644 |
| 線で除かれる M | 0 件(0%) |
| P の最大の 1 位との差 | 0.0829(線は 0.0929 以上) |
| M の最大の 1 位との差 | 0.0906。線で除かれる M は 0 件(0%) |
| 特徴ベクトル検索の上位 10 件の近さの中央値 | 当たり 0.1087・外れ 0.1094 |

どちらの線でも、効き目の下限(M の 20% = 52 件)に届かない。P の下から 6 行を落としても、除かれる M は 0 件だった。当たりと外れの近さは、ほとんど重なっている。つまり分かれ目が無く、規則どおり入れない。

近さの値(補正をかける前のコサイン)は 0.1 前後に集まり、1 に近い値は出ていない。画面の説明は、「1 に近いほど近い」とは書かない(0038)。

短い日本語の検索語では、特徴ベクトル検索の点から、どの言葉にも近い画像の分を引く(0051)。引いた後の点に、この規則を 1 回あてた数字は 0051 に書いた。当たりと外れの値は、引いた後も重なっていて、線は引かない。

## 結果

- 特徴ベクトル検索だけで出た画像は、近さの度合いを言えない。画面は「特徴ベクトル検索で出た」と、近さを言い切らない理由の行で示す(0038)。
- 検索の結果は、画像が 300 枚以上あれば、必ず上限(300)に達する。画面の見出しは、上限で切ったときだけ「上位 300 枚」と書く。
- 関係のない画像が上位に混じることは、受け入れる。

## 見直す合図

モデルを替えたとき(近さの分布が変わる)。実際の使い方で、特徴ベクトル検索の外れが目立つと分かったとき。そのときは、守る集合と効き目の下限を、新しい標本で、結果を見る前に決め直す。
