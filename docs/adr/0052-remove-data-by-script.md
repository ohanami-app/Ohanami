# 0052. アプリが PC に残した物は、zip に入れたスクリプトで消せるようにする

状態: 採用

## 背景

Ohanami にはインストーラーが無い。zip を展開して使う(0042)ので、アンインストーラーも無い。アプリのフォルダを消しても、アプリが作ったデータは、アプリのフォルダの外に残る。使う人から見た問題は、たとえば次のとおり。

- 試してみたが、自分の PC には合わなかった。モデルのファイルを取ったあとなので、全部を消したい。アプリのフォルダを消したが、`%LOCALAPPDATA%\Ohanami` に何がどれだけ残っているのか、分からない。
- しばらく使わない。モデルのファイル(合わせて約 10.8GB。0043)だけを消して空きを作りたい。ただし、インデックスは残したい(VLM の分は、作り直すのに約 36 時間かかる。0006)。手動タグは、作り直せない。
- 友人に「消すときは、このフォルダを丸ごと消して」と教えたら、そのフォルダに自分で置いていた別の物(開発用のデータなど)まで消えた。

手で消す手順を文書に書くだけでは、アプリが書く物が増えたとき、文書の表が古くなる。古い表のとおりに消すと、「消した」が嘘になる(たとえば、DB の複製やサムネイルには、画像の中身が入っている)。

アプリが書く物は、**データの根**(アプリのデータの置き場。既定は `%LOCALAPPDATA%\Ohanami`、環境変数 `OHANAMI_DATA_DIR` があればその場所)の下だけである。レジストリ・スタートアップ・タスク・`%APPDATA%`・`%TEMP%`・アプリのフォルダには書かない。設定の画面も設定ファイルも無い。

スクリプトで消すには、次の 3 つの制約がある。どれも、公開されている文書と、使い捨ての一時フォルダで確かめた(下の「根拠」)。

- **実行ポリシー**: Windows PowerShell 5.1(Windows に入っている PowerShell)の、Windows 11 などのクライアントでの既定は `Restricted` で、`.ps1` を実行しない。
- **Mark of the Web**(インターネットから取ったファイルに Windows が付ける印。ファイルの代替データストリーム `Zone.Identifier` に入る)。zip を展開すると、中のファイルに引き継がれることがある。引き継がれたファイルは、実行のときに、確認の画面や、スマート アプリ コントロール(Smart App Control。Windows 11 の、署名や評判の無いアプリやスクリプトを止める機能。0049)の対象になりうる。
- **文字コード**: Windows PowerShell 5.1 は、BOM の無い UTF-8 のファイルを、その PC の ANSI コードページ(日本語の Windows では 932)として読む。日本語を含む `.ps1` が、BOM なしだと、文字が化けるだけでなく、構文が壊れたり、次の行が黙ってコメントになったりする。

## 決定

**アプリ本体には、データを消す機能を持たせない。** 消すのは、zip に入れた 2 つのスクリプトである。

**実行ポリシーやスマート アプリ コントロールなどでスクリプトが動かない PC は、対象にしない。そこでは、手で消す。** 手で消す手順は、README に残す。

### 形

- zip の、アプリのフォルダ(`Ohanami.App.exe` の隣)に、`Ohanami-RemoveData.cmd` と `Ohanami-RemoveData.ps1` を置く。利用者は `.cmd` を開く。
- `.cmd` は、`%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`(5.1。フルパス)を `-NoProfile -ExecutionPolicy Bypass -File` で起こし、同じ場所の同じ名前の `.ps1` を動かすだけにする。`-ExecutionPolicy Bypass` は、この 1 回の起動だけに効き、PC の設定は変えない。`.cmd` は ASCII だけで書き、行末は CRLF にする。
- `.ps1` は、UTF-8 の **BOM 付き**・行末 LF で配る。
- `.ps1` は、消す物の一覧と大きさを出し、「モデルのファイルだけ」か「すべて」かを聞いてから消す。「すべて」は、失う物(インデックスと手動タグ。元に戻せない)を言って、もう一度聞く。入力が無い・ほかの入力のときは、何も消さずに終わる。`-Mode`・`-Yes`・`-ListOnly`・`-DataRoot` の引数で、聞かずに動かすこともできる(テストのため)。
- データの根は、`-DataRoot`、環境変数 `OHANAMI_DATA_DIR`、既定の場所の順に決める。前の 2 つが絶対パスでなければ止まる(アプリは、相対の値を、起動した場所から解くが、スクリプトにはそれを再現できないため)。
- Ohanami が動いているときは、何も消さずに止まる。見るのは、アプリが根ごとに作る名前付きの Mutex(同時に 1 つだけ起動するための印。名前は `Local\Ohanami.Instance.<根から作った 8 バイトの 16 進>`)で、取得はせず、あるかどうかだけを見る。聞く前と、消す直前の 2 回見る。プロセスの名前では見ない(`llama-server.exe` は一般的な名前で、ほかのソフトにも当たる)。
- 消す順は、「すべて」のとき、最初に DB の組(`ohanami.db` と `-wal`・`-shm`)で、1 つでも消せなければそこで止め、ほかの物に手を付けない。次に、DB の複製・pid・ログ・サムネイル、そしてモデルのファイル。最後に、空になった既知のフォルダを消す。「すべて」で、ここまでで根が空になったときは、根も消す(空でなければ、残す)。消せない物があっても、DB の組より後は続け、終わりに「消せなかった物」として出す。巻き戻しは無い。もう一度動かせば、続きから消せる。
- 既知のフォルダの中を調べられなかったとき(パスが長すぎる、権限が無い、など)は、その中の物を消さず、「中を調べられなかったフォルダ」として出す。名前や型が合わない物は、残して、終わりに「残した物」として出す。
- 画面の文は、0038 の語に合わせる。

### アプリが PC に残す物

次の表が、アプリが残す物の一覧である。**この表を、一覧の唯一の置き場とする。** README とスクリプトは、この表に従う。アプリが書く物を変えるときは、この表とスクリプトの型を一緒に直す(後の「守り方」の見張りが知らせる)。

「根から」の相対パスで書く。区分は、A = モデルのファイルだけを消すとき、B = すべてを消すとき(B は A を含む)。

| 根から | 中身 | 消す区分 |
|---|---|---|
| `ohanami.db` | インデックスと手動タグ | B |
| `ohanami.db-wal`・`ohanami.db-shm` | SQLite の WAL の付随のファイル。正常に閉じると消える。落ちたときに残る | B |
| `ohanami.db.bak-v<N>`・`ohanami.db.bak-v<N>-<n>` | DB の版を上げる起動で作る複製。自動では消えない。中身は DB と同じ | B |
| `llama-server.pid`・`llama-server.pid.<16 進 32 桁>.tmp` | VLM の処理プログラムの記録。異常終了で残る | B |
| `logs\ohanami-<yyyyMMdd>.log` | アプリのログ。古い物を消す処理は無い。画像のパスが入る | B |
| `logs\llama-server-<yyyyMMdd>-<HHmmss>-<fff>.log` | VLM の処理プログラムのログ。新しい 3 つを残す | B |
| `thumbs\v1\<16 進 2 桁>\<16 進 64 桁>_<幅>x<高さ>.jpg`、と、同じ名前に `.<16 進 32 桁>.tmp` を付けた物 | サムネイル(画像の縮小版そのもの)。`v1` は書式の版 | B |
| `models\ViT-SO400M-16-SigLIP2-384__ohanami\` の `visual\model.onnx`・`textual\model.onnx`・`textual\model.onnx_data`・`textual\tokenizer.json` | 特徴ベクトル検索のモデルのファイル | A・B |
| `models\Qwen3-VL-8B-Instruct-GGUF\` の `Qwen3VL-8B-Instruct-Q4_K_M.gguf`・`mmproj-Qwen3VL-8B-Instruct-F16.gguf` | テキスト検索の VLM のモデルのファイル | A・B |
| 上のモデルの各ファイルに `.part` を付けた物 | ダウンロードの取りかけ。数 GB になりうる | A・B |

- モデルのファイルは、根の下にあるとは限らない。アプリは、アプリのフォルダから親のフォルダをたどって、最初に見つかった `models\<モデルのフォルダ名>` を使う。無ければ根の下の `models\` を使う。環境変数 `OHANAMI_MODELS_DIR` があれば、その下を使う。**根の外にあるモデルのファイルは、スクリプトは消さない**(利用者が自分で作った場所で、ほかの物が入りうる)。
- 区分は、A と B の 2 つだけにする。「DB は消すが、ログは残す」という区分は作らない。ログには画像のパスが入り、残す理由が無い。DB の複製とサムネイルは、必ず B で消す。
- 根の直下の `-journal` が付く名前は、一覧に入れない。DB は、最初の表を作る前に WAL にするので、書かれない。残っていれば、「知らない物」として報告に出る。

### 決して消さない物

1. **利用者のスクリーンショットのフォルダ。** スクリプトは DB を開かず、場所を知らない。
2. **データの根そのものを、再帰で消すことはしない。** 根の下には、アプリが作っていない物が同居しうる。公開の文書が、開発者に、根の下に物を置くよう案内している(`tools/convert-siglip2/README.md` の Python の venv、`tools/Ohanami.Bench/README.md` のベンチの DB と結果)。根ごと消すと、これらも消える。スクリプトには、再帰の削除を 1 つも書かない。
3. **根の外。** 消す直前に、消す物のフルパスが、「根 + 区切り」で始まることを確かめる(大文字と小文字は区別しない)。違えば、止める。
4. **アプリのフォルダ。** 利用者が自分で選んだ場所で、ほかの物が同居しうる。場所を言って、利用者が手で消す。
5. **共有の物と、OS の物。** たとえば、CUDA のキャッシュは、ほかのソフトと共有する。Ohanami が書くと確かめていない物は、一覧にも、消す対象にも入れない。
6. **根より下の、再解析点(ジャンクションやシンボリックリンク)の中。** 入らず、「残した物」として出す。根そのものが再解析点のとき(データの置き場を別のドライブに移した人)は、ふつうに中を扱う。
7. **名前や型が、一覧に合わない物。** 既知のフォルダの中にあっても、残して、報告に出す。

消すのは、`File.Delete` で 1 つずつ消せるファイルと、空になったときだけ消える `Directory.Delete`(引数 1 つ)で消せるフォルダだけである。名前は、型(正規表現。名前の全体に当てる)で確かめる。

### 守り方

スクリプトは、アプリの約束(画像・検索語・インデックスは PC の外に出ない。0043)の範囲のコードなので、次をテストで見張る。

- `NetworkBoundaryGuardTests`(0043)が読むのは、`src/` の `*.cs` だけで、`.ps1` は読まない。0043 の「製品のコード(`src/` のすべて)」の見張りを広げる代わりに、`tests/Ohanami.RemoveData.Tests` で、スクリプトのソースを読んで、次の語が無いことを確かめる(コメントも文字で探す)。再帰と別の消し方(`Remove-Item`・`-Recurse`・`rmdir`・`rd`・`del`)、動的な実行と別のプロセス(`Invoke-Expression`・`Add-Type`・`Start-Process` など)、設定の変更(`Set-ExecutionPolicy`・レジストリ)、ネットワークの語(`Invoke-WebRequest`・`System.Net`・`http` など)。フォルダの削除は、引数が 1 つ(空のときだけ消える)の呼び出しだけであることも確かめる。
- `.ps1` の先頭 3 バイトが BOM であること、`.cmd` が固定の 5 行であること(ASCII だけ・CRLF だけ)を確かめる。Release のワークフローはテストを回さない(0048)ので、配布物を作る手順(`Publish-Release.ps1`。0042)も、配布物の 2 ファイルについて、同じ確かめと、リポジトリの同名のファイルとバイト単位で同一であることの確かめを行い、違えば zip を作らない。
- `src/` のファイルを書く API を使ってよいファイルを、「式・許すファイル・理由」の表で決めて見張る。理由の列に、スクリプトのどの型が、その書き手の物を受けるかを書く。新しい書き手を足す人が、この表に当たり、スクリプトの一覧に気づく。
- 一時のデータの根で、アプリの本物の書き手(DB・DB の複製・サムネイル・アプリのログ・取りかけのダウンロード)を動かしてから、「すべて」を消し、根が無くなることを確かめる。書き手が新しい物を書くようになれば、ここが落ちる。本物で作れない物(`llama-server.pid` とその一時ファイル・VLM のログ・`-wal`・`-shm`)は名前で置き、名前の型は、Core のテストが、書き手の側から確かめる。
- スクリプトを動かすテストは、テストごとの一時のフォルダの中だけで動かす。入口で、`-DataRoot` が無い・一時のフォルダの外・相対パスの削除の呼び出しを、プロセスを起こす前に拒む(`-ListOnly` だけは、`-DataRoot` が無くてもよい)。

どのテストが何を確かめるかは、「根拠」の表にある。

## 検討した案

| 案 | 採らなかった理由 |
|---|---|
| アプリの画面に、消す操作を足す | アプリ本体には、データを消す機能を持たせない、と決めたため |
| アプリの exe に、消す引数を足す | 同じ。アプリ本体に消す機能を持たせない |
| README の手順だけにする | 手順の表は、アプリが書く物が増えると古くなり、古い表で消すと消し残る。大きさと消し残りは、手で確かめることになる |
| `.cmd` だけで書く | 文字コードの扱いが、`.ps1` よりさらに弱い(`cmd.exe` は、バッチをそのときのコードページで読む)。名前の型の確かめも、書きにくい |
| `.cmd` を 2 つ(モデルだけ・すべて)にする | 何を失うかを見せる前に、消す操作が始まる。一覧を見て選ぶ形にならない |
| 起動中かどうかを、プロセスの名前で見る | 上のとおり。開発機では、別の Ohanami が動いていると、一時の根を相手にするテストが毎回止まる |
| 根を、再帰で丸ごと消す | 上の「決して消さない物」の 2 のとおり |

## 根拠

出典は、公開の文書と、使い捨ての一時フォルダでの確認である。確認は、Windows PowerShell 5.1(5.1.26100)で、日本語の Windows(ANSI コードページ 932)で行った。アプリのデータや、スクリーンショットは使っていない。

**実行ポリシー**(`about_Execution_Policies`、5.1 の版): クライアントの Windows の既定は `Restricted` で、個々のスクリプトを実行しない。実行ポリシーには範囲(スコープ)があり、`-ExecutionPolicy` で指定した値は、その 1 回のプロセスだけに効く。グループ ポリシーで決めた値は、それより優先される。したがって、`-ExecutionPolicy Bypass` は、グループ ポリシーのある PC では効かない。そういう PC は、対象にしない(決定)。

**Mark of the Web**: Zone.Identifier(`ZoneId=3`)を付けた zip を、展開の方法ごとに展開して、中のファイルに印が付くかを見た。

| 展開の方法 | 中の `.ps1`・`.cmd` に印が付くか |
|---|---|
| エクスプローラーと同じ展開の部品(`Shell.Application`) | 付く |
| 7-Zip(既定の設定) | 付く |
| `Expand-Archive` | 付かない |
| `tar.exe` | 付かない |

ふつうの利用者は、エクスプローラーで展開するので、`.cmd` と `.ps1` には印が付く。スマート アプリ コントロールがオンのときは、`.bat`・`.cmd`・`.js`・`.ps1` などが、印が付いていると止まる、と Microsoft の文書が言っている(`support.microsoft.com` の、Smart App Control が危険な拡張子のアプリを止めた、という説明)。そのとき、利用者が選んで通す方法は無い。署名の無い Ohanami 自身も、この機能がオンの PC では、すでに起動できない(0049)。

**文字コード**(`about_Character_Encoding`、`understanding-file-encoding`): Windows PowerShell 5.1 は、BOM の無いファイルを、ANSI コードページとして読む。BOM のある UTF-8 は、UTF-8 として読む。同じ内容の `.ps1` で、確かめた。

- BOM なしの UTF-8 を 932 で読むと、日本語の文字列が化ける。
- 行末が LF で、末尾が「。」や「ト」の日本語の行コメントは、次の行までコメントにした(次の行が実行されなかった)。BOM 付きにすると、次の行が実行された。
- `.cmd` から `.ps1` を起こす形は、フォルダの名前に、空白・括弧・日本語・`&`・`%`・`!`・`'`・`[`・`]`・`^` を含む場合のすべてで動き、`.ps1` の終了コードが、`cmd` の外まで届いた。行末が CRLF でも LF でも同じだった。`pause` で窓が残り、標準入力を閉じても止まらない。
- `-File` の引数の誤り(位置の引数・知らない引数・許す値の外)と、捕まえていない例外は、`.ps1` の本体が 1 行も動かず、終了コードは 1 になる。ファイルを誤って `.cmd` に落としても、何も消えない。

**消し方**(`Remove-Item` の 5.1 の文書): `-Recurse` の削除は、5.1 では、260 文字を超えるパスを消せない。この点は、文書に出典を見つけられなかった。一時フォルダで、260 文字を超える深さのフォルダを作って、`Remove-Item -Recurse -Force` で消そうとすると、消えず、エラーは出ても止まらないことを確かめた。別のプロセスが開いているファイルは、消えずに残り、ほかのファイルは先に消える。このため、再帰の削除を使わず、名前を 1 つずつ確かめて消す。260 文字を超えるパスの対策(`\\?\` を付けるなど)は、作り込まない。

**起動中の検出**: Mutex の名前の作り方(根を大文字にして、SHA-256 の先頭 8 バイト)は、5.1(.NET Framework 4.8)と、アプリの .NET 10 で、ASCII・かな・漢字・アクセント付きのラテン文字・キリル文字・全角の英字を含む根では、同じ値になった。グルジア文字・チェロキー文字・ギリシャ語の語末のシグマ(ς)を含む根では、違う値になった(大文字にする表が違う)。別のプロセスが持つ `Local\` の Mutex を、5.1 は `TryOpenExisting` で見つけ、手放したあとは見つけなかった。

**テスト**: どのテストが、何を確かめるか。`tests/Ohanami.RemoveData.Tests` は、Windows PowerShell 5.1 を子プロセスで起こして、`.ps1` を実際に動かす(全体で約 25 秒)。判定は、終了コードと、ファイルが残ったか消えたかで行い、日本語の画面の文では行わない。

| テスト(クラス) | 確かめること |
|---|---|
| `RemoveDataRunTests`(`tests/Ohanami.RemoveData.Tests`) | 全部の名前を置いた根で、「モデルのファイルだけ」はモデルのファイルと `.part` だけを消し、ほかはバイト単位で同じ。「すべて」は、続けて動かすと根が無くなる。知らない物は、それを持つフォルダと根ごと残る。サムネイルの中のジャンクションは入らず、先の物が残る。DB の複製(`bak-v<N>`・`bak-v<N>-<n>`)・`.part`・2 種類の一時ファイルは全部消える。アプリが Mutex を持つ間は何も消えず、手放したあとは消える。DB が開かれて消せないときは、ほかの物に手を付けない。聞かれて入力が無いと、何も消さない。相対の根(引数・環境変数の両方)は止まる。環境変数の根が、アプリと同じフルパスになる。`-Yes` だけは止まる。根が無いときは、消す物が無い。日本語と空白の入った根で、動く。`.cmd` から、引数と終了コードが届く |

## 結果

- zip に 2 ファイル(`Ohanami-RemoveData.cmd`・`Ohanami-RemoveData.ps1`)が増える。配布物の許可の表(0042)に、この 2 行を足す(出どころは `repository`)。リポジトリでの置き場は `src/Ohanami.RemoveData/` で、配布物では直下に置く。
- `.cmd` を開くときに、Windows が確認を出すことがある(Mark of the Web が付くため)。その画面は、まだ確かめていない。
- 5.1 は、260 文字を超えるパスを消せない。そのパスは、「消せなかった物」に出る。
- 起動中の検出は、上の文字を含む根と、綴りの違う根(8.3 の短い名前など)で、見逃す。見逃したときは、「すべて」では、DB の組を最初に消すので、アプリが DB を開いたままなら、消せずに止まる(ほかの物には手を付けない)。モデルのファイルだけを消すときは、アプリが動いたままでも消えることがある。次の起動で、セットアップの画面になる。
- 根の外に置いたモデルのファイルは、消えない。
- アプリのフォルダを先に消した人は、スクリプトも失っている。手で消す。
- アプリが書く物を変えたら、この ADR の表と、スクリプトの型を直す。見張りのテストが知らせる。
- Windows の確認の画面・Sandbox での通し(既定の場所での A と B の削除、既定の実行ポリシーの PC での動き、コンソールの日本語の見え方)は、まだ確かめていない。

## 見直す合図

- アプリが、根の外や、レジストリに書くようになったとき(「根の下だけ」の前提が崩れる)。
- 配布を、インストーラーや MSIX に替えるとき(0042・0049)。インストーラーなら、アンインストールの機能を、そちらが持つ。
- 署名を付けるようになったとき(0049)。確認の画面と、スマート アプリ コントロールの扱いが変わる。
- `.cmd` を開いたとき、Mark of the Web の確認のほかの理由(ウイルス対策のソフトがスクリプトを止める、など)で、多くの PC で動かないと分かったとき。形を考え直す。
- Windows から、Windows PowerShell 5.1 が無くなったとき。
