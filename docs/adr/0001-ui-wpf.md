# 0001. UI は WPF にする

状態: 採用

## 背景

利用者は、手元の数万枚のスクリーンショットの一覧をカクつかずにスクロールし、検索結果の画像をブラウザの投稿欄などへそのままドラッグして渡したい。Windows 11 専用のデスクトップアプリで、次を満たす UI 基盤が要る。

- 数千〜数万枚のサムネイルを滑らかに並べられる(0041)。
- 検索結果の画像を、Windows 標準のドラッグ&ドロップで他のアプリ(ブラウザのアップロード欄など)に渡せる。
- 配布が簡単で、AI を使った開発でも書き間違いが少ない(学習量が多く、実績のある基盤が良い)。

## 決定

UI は WPF で作る。XAML も Binding も使わず、画面はすべてコードで組む。起動から画面の組み立てまでは `src/Ohanami.App/Program.cs` の `Main` と `MainWindow.cs` に明示的に書き、DI コンテナもリフレクション頼みの仕組みも使わない。UI と Core は分け、Core は UI の型を参照しない(0002)。将来 UI を差し替えられるのは、この分離のおかげである。

## 検討した案

| 案 | 採らなかった理由 |
|---|---|
| MAUI | 対象は Windows だけで、複数の OS を覆う抽象化はコストにしかならない |
| WinUI 3 | Microsoft が新しい汎用のデスクトップアプリに第一に勧めている基盤。ただし、AI エージェントが持つ実装例の量、配布の簡単さ、OS へのファイルのドラッグアウトの容易さで WPF が勝る。WinUI 3 を選ばない代わりに、下の「見直す合図」を置く |
| Microsoft.UI.Reactor | プレビュー版で、API の互換が保証されていない |

## 根拠

判断の根拠にした外部の事実を示す(確かめた時点の値)。

- Microsoft の「Windows developer FAQ」(<https://learn.microsoft.com/en-us/windows/apps/get-started/windows-developer-faq>)は、新しい汎用のデスクトップアプリに第一に勧めるのは WinUI 3 と書く。一方で WPF を「非推奨ではない」「成熟して安定し、広く使われている」とも書く。
- WPF の開発は活発ではない。dotnet/wpf リポジトリの人の手によるマージは、確かめた時点の直近 12 か月が、その前の 12 か月の約 1/4 だった。.NET 11 の WPF の変更は修正だけで、WPF のロードマップは更新されていない。
- WPF の標準の見た目は昔のままである。Windows 11 の見た目(Fluent テーマ)は .NET 9・10・11 のどれでも試験的な機能(コンパイラの警告 WPF0001)で、外す予定の公式の記載は無い。この扱いは 0040 に書く。

どちらの基盤が優れているかを測ったわけではない。Ohanami の要件(大量のサムネイル、ファイルのドラッグアウト、配布のしやすさ、AI での開発のしやすさ)に対し、WPF の欠点が小さいと判断した。

## 結果

- 新しい機能(Fluent の見た目など)は試験的な扱いのものに頼ることになる。見た目は外せる皮として入れ、守りを置く(0040)。
- WPF の開発が止まっても、検索や DB の本体(Core。0002)は UI に依存しないので、UI を作り直すだけで済む。ただし作り直しの費用は小さくない。

## 見直す合図

Microsoft が WPF を .NET から外す、または保守だけにすると公式に書いたとき。
