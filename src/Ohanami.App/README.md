# Ohanami.App: WPF のアプリ

画面はすべてコードで組む(XAML・Binding・DI コンテナは使わない)。`Ohanami.Core` を参照するだけで、検索・インデックス作成・DB の中身は Core が持つ。
画面の語は `docs/adr/0038-wording-principles.md` の表に合わせる。ビルドとテストは [CONTRIBUTING.md](../../CONTRIBUTING.md) と [tests/README.md](../../tests/README.md)。

`Ohanami.App.Tests` は、画面を出さずに測れるもの(文言・寸法・選択の規則・ショートカットの判定など)だけを見る。次の「手動確認」は、**自動のテストが見ない所**(本物のドラッグ・クリップボード・エクスプローラー・日本語入力・表示スケール・本物のスクリーンショットのアプリ・スリープ・長い時間)を、人が確かめる手順。
スリープと強制終了の確認は、別の手順(`tools/Ohanami.Bench/README.md` の「長時間の手動確認」)。

## 起動の仕方

```
dotnet build src/Ohanami.App
pwsh tools/run-app-without-cuda-path.ps1
```

`tools/run-app-without-cuda-path.ps1` は、PATH から CUDA の DLL があるディレクトリを外して(子プロセスの環境だけ)App を起動する。
開発機は PATH に CUDA Toolkit があり、同梱し忘れた DLL が PATH から黙って読まれて、問題が隠れる(ADR 0015)。**手動確認は、いつもこのスクリプトで起動する**。

| 環境変数 | 意味 |
|---|---|
| `OHANAMI_DATA_DIR` | データ(`ohanami.db`・`thumbs\`・`logs\`・`llama-server.pid`)の置き場。既定は `%LOCALAPPDATA%\Ohanami` |
| `OHANAMI_MODELS_DIR` | `models/` に当たるフォルダ |
| `OHANAMI_RUNTIME_DIR` | `runtime/` に当たるフォルダ(ビルドが CUDA・cuDNN の DLL を探す場所。`llama-server.exe` も、ここから使える) |

普段のデータを混ぜたくないときは、先に `$env:OHANAMI_DATA_DIR = 'D:\tmp\ohanami-try'` を設定してから起動する。
モデルのファイルが無いと、セットアップの画面が出る(README の「最初の起動」)。以下は、モデルがそろっているものとする。

### ログ

`<データの場所>\logs\ohanami-yyyyMMdd.log`(1 行 1 イベント。**時刻と日付は UTC**。日本時間は +9 時間で、日付も UTC で替わる)。

```
$log = Get-ChildItem "$env:LOCALAPPDATA\Ohanami\logs\ohanami-*.log" | Sort-Object Name | Select-Object -Last 1
Get-Content $log.FullName -Tail 60 -Encoding UTF8
# 関係する行だけ
Select-String -Path $log.FullName -Encoding UTF8 -Pattern '走査:|ジョブ:|監視:|llama-server を|スリープ|復帰'
```

見る行の形:

- `走査: 始める(きっかけ: 起動 / 手動 / 監視 / 定期 / 復帰 / 見つからない / 再試行、フォルダ n 個)` と `走査: 終わった(新規 n、変更 n、消えた n、…、所要 x 秒)`(「一時的に読めない n」が付くことがある)。
- `ジョブ: インデックス作成を開始`(ボタン)、`ジョブ: 待機から続ける(新しい待ち …。指定: …)`(自動)、`ジョブ: 一時停止`・`ジョブ: 一時停止した(待機中から)`・`ジョブ: 再開`、
  `ジョブ: VLM を止める(理由: 切り替え / 一時停止 / 待機 / 終了 / 失敗)`、`ジョブ: 待機に入る(新しい画像が来たら続ける。…)`、`ジョブ: 埋め込みが終わった(…)`・`ジョブ: VLM が終わった(…)`(止まったときは `…を止めた(理由: …)`)。
  ログの中の段階の名前は、画面の「特徴ベクトル検索」が「埋め込み」、「テキスト検索」が「VLM」(内部の呼び名のまま)。以下の手順で「特徴ベクトル検索の段階」と書いたものは、ログでは「埋め込み」。
- 件数の読み方: 「処理」「失敗」の n は、**段階ごとの数**(特徴ベクトル検索の段階とテキスト検索の段階で、別に数える)。1 枚の画像が両方の段階を通ると、段階ごとに 1 回ずつ数えるので、内訳を足した数は画像の枚数ではない。「飛ばした(画像)」だけは、画像の数(段階をまたいで重複なし)。「待機から続ける」の「新しい待ち」も段階ごと(新着 1 枚なら、どちらの段階も 1 枚)。
- `llama-server を起動した(pid …)` と `llama-server を止めた(pid …)`(VLM の起動し直しの回数を数えるのに使う)。
- `監視: …`(監視を作り直した・作れない・あふれなど。普段は出ない)。

### 画面の状態の欄(左のパネル)

起動した直後は、「停止中」(インデックスは作らない)。ボタンで始めると「実行中: …」、待ちが無くなると「待機中(新しい画像が来たら続ける)」、一時停止で「一時停止中」。
同じボタンが、状態によって「インデックス作成を開始」・「一時停止」・「再開」になる(ADR 0039)。

## 手動確認 A: 起動から終了まで(基本の流れ)

1 000 枚ほどの画像のフォルダ(自分の画像でよい。リポジトリには入れない)を使う。

1. 起動する(上)。
2. 「追加…」で画像のフォルダを選ぶ → フォルダが一覧に出て、自動で走査される(通知に「スキャンが終わりました」)。
3. 「インデックス作成を開始」→ 進捗(件数・枚/秒・残り時間)が動く → 途中で「一時停止」→ 止まる → 「再開」で続く。
4. 検索欄に言葉(日本語・英語)を入れて Enter → 結果が出る。サムネイルにマウスを載せると、出た理由と順位・パスが出る。スクロールが滑らか。
5. 結果から、**ブラウザの画像のアップロード欄へドラッグ**(1 枚。Ctrl+クリックで複数)→ 入る(元のファイルは動かない)。エクスプローラーのフォルダ・チャット・ペイントへのドロップも。
6. 右クリック(または Ctrl+C = 画像をコピー、Ctrl+Shift+C = ファイルとしてコピー、E = エクスプローラーで表示)→ 貼り付け先(ペイント・チャット・エクスプローラー)に貼れる。エクスプローラーで、そのファイルが選ばれる。
7. 結果に出ている画像の元のファイルを(コピーを用意して)別の場所へ動かしてから、ドラッグ・コピー・「エクスプローラーで表示」→ 元のファイルが無い旨が出て、落ちない。
8. もう 1 つ起動する → 新しいウィンドウは開かず、最初のウィンドウが前に出る。
9. 閉じる(×)→ すぐ閉じる(インデックス作成の途中でも、止めてから閉じる)。もう一度起動 → 続きから(作成済みの分は、作り直さない)。
10. 表示スケールの違う画面(150% など)へウィンドウを動かす → サムネイルが作り直されて、ぼやけない。
11. ログ(上)に、1 行 1 イベントで残っている。

## 手動確認 B: 監視・待機・詳細・手動タグ

普段のスクリーンショットのアプリと、自分の画像で行う。合計で約 2 時間(30 分の観察を含む)。ここに書いた数字(3 秒・30 秒・5 秒・15 分・2 秒・20 枚・10 分・1 分前後)は、設計の初期値で、実際に使って決め直す(ADR 0009・0010・0027)。
モデルがそろっていて、ゲームなど GPU を使うものは閉じておく。

| 確かめたいこと | 場面 |
|---|---|
| 普段のアプリで撮ったスクリーンショットが、何も操作しなくても検索に出る。出るまでの時間 | 1 |
| 「待機中」の状態で新しい画像が自動で処理される。一時停止で止まる。起動直後は止まったまま。VLM の実行中に撮っても、切り替えが起きない(20 枚・10 分未満。ADR 0027) | 3 |
| 詳細画面: 一致の強調、前後の移動、ドラッグで他のアプリへ、エクスプローラーで表示、コピー | 5 |
| 手動タグ: 付ける・外す・まとめて付ける・次の検索で引ける・VLM の前の画像でも引ける(ADR 0036) | 6 |
| 失敗の一覧、要再作成、フォルダに無い画像の記録を消す | 7 |
| ファイルを移動・削除・フォルダごと移動すると、操作しなくても検索の結果から消える(入る) | 8 |
| スリープから復帰したあとに撮ったスクリーンショットが拾われる(ADR 0009) | 9 |

準備: スクリーンショットのアプリ(Snipping Tool・Xbox Game Bar・Steam・NVIDIA のオーバーレイなど)ごとに、保存先のフォルダを調べて書き留め、App に「追加…」で登録する。
保存先は、アプリの設定で確かめる(Snipping Tool と Win+Print Screen は Pictures の Screenshots、Xbox Game Bar は Videos の Captures、など。機種や設定で変わる)。

そのほかの準備: ビルドは、普段の起動に使うもの(`dotnet build src/Ohanami.App`。`OHANAMI_RUNTIME_DIR` が要る)。VLM を使う場面(1・3)のために、llama-server とモデルが、普段どおり使える状態にしておく。**データは、試し用の `OHANAMI_DATA_DIR` にするか、普段のデータでよいか、先に決める**(普段のデータで行うなら、App を閉じて、`ohanami.db` を別の場所にコピーしておくと安心)。
件数を DB から数えたいときは、読み取り専用の道具がある: `dotnet run --project tools/Ohanami.Bench -- stage-count --folder <フォルダ> --stage embed|ocr|caption --data "$env:LOCALAPPDATA\Ohanami"`(使い方は `tools/Ohanami.Bench/README.md` の「stage-count」)。

### 場面 1: 撮ったスクリーンショットが、操作なしで検索に出る(約 30 分。アプリごとに繰り返す)

目的: 撮ってから検索に出るまでの時間と、アプリごとの書き方の違い(書き込みの途中のファイルの扱い)を見る。
前提: 先に「インデックス作成を開始」を押して、待ちが無くなるまで流し、状態を「待機中」にしておく(待機でないと、新しい画像は処理されない。場面 3)。

1. 時計(秒まで見えるもの)を用意する。スクリーンショットを 1 枚撮る(普段の操作で。App は触らない)。撮った時刻を書き留める。
2. ログを読む。撮った時刻から、
   - `走査: 始める(きっかけ: 監視、…)` と `走査: 終わった(新規 1、…)` の時刻(監視は、変化が 3 秒止まってから走査する。続いても 30 秒で 1 回)。
   - `ジョブ: 待機から続ける(新しい待ち …)`(新着 1 枚は、段階ごとに 1 枚ずつ待ちに入る)。
   - 特徴ベクトル検索の段階が終わり、続いて VLM の起動と `ジョブ: VLM が終わった`、`ジョブ: 待機に入る`。
3. 検索で、**見た目の語**(その画像に写っているものの言葉)を入れて、その画像が出る時刻を書き留める(特徴ベクトル検索の段階が済めば出る。VLM を待たない)。
4. VLM が終わったあと、**画面の文字の語**または説明文の語で検索し、出る時刻を書き留める(テキスト検索は、VLM のあと)。
5. 詳細を開いて、パスが撮ったファイルであること、寸法とサイズが妥当なこと(画像が途中で切れていない)を見る。ファイルをエクスプローラーで開いて、画像が最後まで写っていること。

合格の見方:

- 走査に `新規 1` が出た(操作なしで拾われた)。目安は、撮ってから 10 秒以内(監視 3 秒 + アプリの書き込みの時間 + 更新から 2 秒以内のファイルは 5 秒後に回す、の合計)。
- `一時的に読めない 1` が付いた走査があれば、そのアプリは書き込みの途中を見せる書き方(開いたまま書く・チャンクごとに書く)。その 5 秒後(再試行)に `新規 1` が出れば、設計どおりに拾えている(`監視:` の行に「定期の走査に任せる」が出たら `[注意]`)。
- 登録された画像が、途中で切れていない。穴: 間を空けて追記する書き方だと、途中の内容が 1 度登録され、完成後に別のハッシュで登録し直される。検索に出るのは完成したあとの 1 枚だけで、使われない画像の記録が 1 つ残るだけ(ADR 0010)。
- 見た目の検索に出るまで: 撮ってから、ジョブが待機で動き出す時間 + 特徴ベクトル検索の段階(1 枚約 0.1 秒、GPU の準備の数秒を含む)。テキスト検索は、さらに VLM(llama-server の起動 20〜40 秒 + 1 枚約 12 秒)。全部で 1 分前後が目安。

記録: アプリ名 / 保存先 / 撮った時刻 / 走査の開始と終わり / 見た目で出た時刻 / 文字で出た時刻 / `一時的に読めない` が出たか / 画像は完全か / 気づいたこと。

### 場面 3: 待機と一時停止(約 25 分)

**3a. 起動直後は止まったまま**: App を閉じて、起動し直す。「実行中」「待機中」が出ていない(停止中)こと。この状態でスクリーンショットを 1 枚撮り、**検索に出ない**こと(走査で登録はされるが、ジョブは自動では始まらない。ログに `走査: 終わった(新規 1…` はあるが、`ジョブ: 待機から続ける` は無い)。
「インデックス作成を開始」を押すと、その 1 枚が処理され、終わると「待機中」になる。(起動時に始めないのは、ゲーム中に検索だけ使うとき、GPU を取らないため。ADR 0027)

**3b. 待機中に新しい画像が自動で処理される**: 状態が「待機中」のとき、スクリーンショットを 1 枚撮る。ログに `ジョブ: 待機から続ける(…)` が出て、処理され、`ジョブ: 待機に入る` に戻る。ボタンを押していないこと。

**3c. VLM の実行中に撮っても、切り替えは起きない**:

1. スクリーンショットを 1 枚撮る。状態が VLM の実行中(llama-server の起動に 20〜40 秒)になったら、続けて 3 枚撮る(30 秒以内に)。
2. ログに `ジョブ: VLM を止める(理由: 切り替え` が**出ない**こと(VLM が 1 枚ずつ流れている間は、新しい画像の特徴ベクトル検索の段階のために止まらない。新しく入った待ちが 20 枚未満で、最初に入ってから 10 分未満のため)。
3. VLM が終わる(`ジョブ: VLM が終わった`)。そのあと、特徴ベクトル検索の段階が残りの新しい画像を処理すること。見た目の検索にその 3 枚が出るのは、**VLM が終わったあと**になる(最大 10 分遅れる設計)。この遅れが気になるかを記録する。
4. 最後に `ジョブ: 待機に入る` になること。

**3d.(任意。VLM を 10 分以上流せるとき)10 分で切り替わる**: VLM が長く動いている間に 1 枚撮り、10 分たつと `ジョブ: VLM を止める(理由: 切り替え` → 特徴ベクトル検索の段階 → VLM の再開、となること(llama-server の起動し直しが入る)。

**3e. 一時停止**:

1. 「待機中」のとき「一時停止」を押す。状態が「一時停止中」。ログに `ジョブ: 一時停止` と `ジョブ: 一時停止した(待機中から)`。
2. スクリーンショットを 1 枚撮る。走査では登録される(`走査: 終わった(新規 1…`)が、**ジョブは動かない**こと(`ジョブ: 待機から続ける` が出ない)。
3. 「再開」を押すと、処理が始まる(`ジョブ: 再開`)。
4. 実行中の一時停止も同じ(`ジョブ: 一時停止した(…)`)で、llama-server が止まる(`llama-server を止めた`。VRAM が解放される)。

### 場面 5: 詳細画面(約 20 分)

検索の結果の一覧で、画像をダブルクリック(または選んで Enter)。

1. **一致の強調**: 画面の文字や説明文に当たる語で検索して、詳細を開く。「文字と説明 (一致した箇所は強調)」の欄で、一致した語が強調される(文字・説明文・VLM のタグ・手動タグ)。見た目だけで出た画像(テキスト検索に当たっていない画像)には、強調が無い旨の注意が出る。
2. **出た理由と順位**: 「出た理由」の行に、2 つの検索方法の順位が、日本語の名前で出る(`visual`・`fulltext`・`cosine` などの内部の名前が画面に出ない)。
3. **前後の移動**: ← → キーと ◀ ▶ ボタン。端で止まる。位置(n / 件数)が合う。移動すると、右側は先頭(タイトル・順位)から始まる。
4. **戻る**: Esc、マウスの戻るボタン、「◀ 戻る (Esc)」で、一覧に戻る(選択が残る)。
5. **状態・パス・寸法**: 画像の状態(未作成・失敗・要再作成)と日時、寸法・サイズ、パス(フォルダに無い印)が出る。
6. **ドラッグ**: 詳細の画像を押したまま、ブラウザのアップロード欄(またはチャットなど、ファイルを受けるアプリ)へドラッグして、ファイルが渡る。元のファイルは移動・削除されない(Copy だけを許す)。
   ダブルクリックの 2 回目では、ドラッグを始めない。Windows の最小ドラッグ距離を超えて動くと始まる(誤作動ではない)。
7. **エクスプローラーで表示**(ボタンと E キー)、**画像をコピー**(ボタンと Ctrl+C。ペイントなどに貼る)、**ファイルとしてコピー**(Ctrl+Shift+C。エクスプローラーに貼る)。元のファイルが無いときは、赤い帯で「見つからない」旨が出る(ファイルを一時的に別の場所へ動かして、確かめてもよい)。
8. 画像が読み込めないとき(ファイルが無い・壊れている)は、画像の場所に理由が出て、右側の情報は出る。

記録: 各項目の合否 / 気づいたこと(特に 6 のドラッグ、ウィンドウを小さくしたときの崩れ、大きな画像の読み込みの遅さ)。

### 場面 6: 手動タグ(約 25 分)

1. **詳細画面で付ける**: 詳細を開き、手動タグの欄の入力欄に、タグの名前(日本語。IME で入力して Enter)を入れて追加する。札(名前と「×」)が出る。**日本語の入力で、変換中の Enter が、タグの追加にならない**こと(変換の確定の Enter は、変換のため)。
2. **候補**: 既存のタグが「候補:」に、使われている数の多い順で出る。入力した文字を含むものだけに絞られる。押すと、そのタグが付く。
3. **外す**: 札の「×」で外れる。外したタグは、ほかの画像が使っていれば、候補に戻る。
4. **拒む名前**: 「|」「、」を含む名前、空、65 文字以上は、**理由が入力欄の下に赤く出て**、何も付かない(ADR 0036)。
5. **まとめて付ける**: 一覧で複数を選び(Ctrl・Shift で。Ctrl+A でも)、「手動タグを付ける… (選択中 n 枚)」→ 名前を入れて「付ける」。付けたことが通知に出る。右クリックのメニューからも同じ。拒む名前は、ダイアログが閉じずに、理由が出る。
6. **次の検索で引ける**: 付けたタグの名前で検索すると、付けた画像が出る(付けた直後の一覧は、自動では検索し直されない。もう一度検索する)。詳細で、そのタグが強調される。
7. **VLM の前の画像でも引ける**: まだ VLM の処理が済んでいない画像(テキスト検索の状態が「未作成」)に手動タグを付け、そのタグで検索して**出る**こと。
8. 付けたタグが、アプリを閉じて開き直しても残っている。

記録: 各項目の合否 / 日本語入力の挙動 / 気づいたこと。

### 場面 7: 失敗の一覧・要再作成・フォルダに無い画像の記録を消す

左のパネルの「インデックスの状態…」を開く(窓の語は ADR 0038 の表)。

- **失敗の一覧**: 段階ごとの「…のインデックス作成に失敗」の欄。失敗が 0 件のあいだは、ボタンが押せない(理由が窓の中に 1 行で出る)。押せるときは、段階ごとに、ファイル・理由・日時・回数が出る。「エクスプローラーで表示」と「詳細」へ行ける。件数が多いときの上限の表示。
- **やり直す**: 「この n 枚をやり直す」「もう一度試す」(飛ばした画像)を押すと、その画像だけ、もう一度作る。
- **要再作成**: 段階ごとに「再作成を始める…」を押すと、件数と見込みの時間(VLM は 1 枚約 12 秒)を出して確認し、始めると作り直す。
- **フォルダに無い画像の記録を消す**: 「記録を消す…」。枚数と、消すと何が消えるか(その画像の結果と手動タグ。同じファイルが戻ったときは、作り直す)を出して確認し、消すと記録が消える。**ジョブが動いている間は押せない**(待機中は押せる)。
- ログ: 失敗した画像と、飛ばした画像の理由(「飛ばした」の内訳)。

### 場面 8: ファイルの移動・削除が、操作なしで結果から消える(約 15 分)

**自分で撮った試しの画像だけを使う**(大事な画像を動かさない・消さない)。ジョブは「待機中」(または停止中でもよい。走査は動く)。

1. 登録したフォルダに、試しのスクリーンショットを 3 枚撮る(A・B・C)。走査で入り(`走査: 終わった(新規 3…`)、ジョブで処理され、検索で出る。
2. **A を、登録していないフォルダへ移動**する(エクスプローラーで切り取り・貼り付け)。**B を削除**する(ごみ箱へ)。
3. App を触らずに、約 10 秒待つ(監視の 3 秒 + 走査)。ログに `走査: 始める(きっかけ: 監視…)` → `走査: 終わった(…消えた 2…)`。ステータスバーに、自動の走査が終わった通知が出る。
4. 検索を**し直さずに**、いま出ている結果の一覧を見る: A と B が一覧から消えたこと(自動の走査のあと、今の検索がやり直される)。C は残る。
5. **詳細画面を A に開いたまま**、A を別のフォルダへ動かす: しばらくして、詳細が閉じて一覧に戻り、結果から外れた旨の知らせが出る(落ちない)。
6. **フォルダごと移動で入れる**: 別の場所で、試しのスクリーンショットを 3 枚入れた新しいフォルダを作り、それを登録フォルダの中へフォルダごと移動する。**中身の 3 枚が検索に出る**こと(フォルダの移動では、中身のイベントが来ないので、フォルダを走査し直す設計)。
7. (任意)名前の変更: ファイル名を変える。古いパスが消え、新しいパスで同じ画像が出る。
8. (任意)**監視できなかった場合**: 登録フォルダが外付けやネットワークのドライブのとき、左のパネルのそのフォルダの行に「監視できません (定期のスキャンだけです)」と出るか。15 分以内に、定期の走査で拾われること(`走査: 始める(きっかけ: 定期…`)。

### 場面 9: スリープから復帰したあとに撮ったスクリーンショットが拾われる(約 10 分)

1. 状態が「待機中」(または停止中)のとき、App を開いたまま、スタートメニューからスリープにする(1〜2 分)。
2. **復帰してから**、スクリーンショットを 1 枚撮る(撮るアプリは何でも)。App は触らない。
3. ログに、復帰の直後に `走査: 始める(きっかけ: 復帰、フォルダ n 個)` と終わりが出る(復帰で、監視を作り直して全部を走査する)。続けて、撮った画像の `走査: 終わった(新規 1…` と `ジョブ: 待機から続ける…`(監視のきっかけで)が出ること。
4. 検索に、その画像が出る。
5. (任意)スリープの前にも 1 枚撮っておき、スリープ中に別のフォルダからファイルを入れる(取り込み)と、復帰の走査で拾われること。

合格: 3 と 4。復帰の走査(きっかけ: 復帰)が出ない、または復帰のあとの画像が拾われなければ、不合格(監視が復帰のあとで止まっていることになる。定期の走査が 15 分以内に拾うはずなので、15 分待って拾われるかも記録する)。

### 観点の一覧

| 観点 | 場面 | 合格の見方 |
|---|---|---|
| スクリーンショットが操作なしで検索に出る | 1 | 走査に `新規 1`、見た目で出る・文字で出る。出ない・遅いアプリがあれば、そのアプリの書き方を調べる |
| 書き込みの途中のファイルを登録しない | 1 | 画像が最後まで写っている。`一時的に読めない` は、5 秒後に回収される。途中の内容が検索に出たら不具合 |
| 起動時は止まったまま | 3a | 「実行中」「待機中」が出ず、新しい画像は処理されない。動き出したら不具合 |
| 待機中に新しい画像が自動で処理される | 3b | `ジョブ: 待機から続ける` が出て、処理されて待機に戻る |
| VLM の実行中に撮っても、途中で切り替わらない | 3c | `VLM を止める(理由: 切り替え` が出ない。VLM が終わったあとに、特徴ベクトル検索の段階が進む |
| 10 分で切り替わる(任意) | 3d | `VLM を止める(理由: 切り替え` → 特徴ベクトル検索の段階 → VLM |
| 一時停止で止まり、再開で続く | 3e | 止めているあいだ `待機から続ける` が出ない。再開で処理される |
| 詳細画面の強調・前後・戻る・状態・パス | 5 | 上のとおり |
| ドラッグ・エクスプローラーで表示・コピー | 5 | 他のアプリへ渡る。元のファイルが動かない |
| 手動タグの付け外し・まとめて・拒む名前の理由 | 6 | 上のとおり |
| タグで検索できる・VLM の前の画像でも | 6 | 付けた画像が出る。出なければ、索引の更新を疑う |
| 失敗の一覧・要再作成・記録を消す | 7 | 上のとおり |
| 移動・削除が操作なしで結果から消える | 8 | 約 10 秒で消える。詳細を開いていても落ちない |
| フォルダごと移動で入れた中身が出る | 8 | 中身が検索に出る。出なければ、フォルダの走査し直しを疑う |
| 復帰のあとに撮った画像が拾われる | 9 | `走査: 始める(きっかけ: 復帰` が出て、画像が拾われる。出なければ、復帰の通知と監視の作り直しを疑う |

### 観測の限界

- 実際のスクリーンショットのアプリ(Snipping Tool・Steam・Xbox Game Bar・NVIDIA)が、一時ファイルを経由するか・開いたまま書くかは、アプリごとに違う。場面 1 の `一時的に読めない` と `新規` の並びが、その手がかり。
- 日本語 IME での入力(手動タグの入力欄、タグの名前を聞く画面)は、判定の関数だけが自動のテストにある。実機の日本語入力は、場面 6 で見る。
- ドラッグ(他のアプリへ)・エクスプローラーで表示・クリップボードへのコピーは、自動のテストでは本物を動かさない(元のファイルが無いときの表示と、偽のシェルに渡ることだけ)。場面 5 と手動確認 A で確かめる。
- 監視がスリープの前後で止まるかは、公式の記述が無い。設計は、復帰で作り直して走査する形なので、確かめずに済む。場面 9 がその確認。
- ネットワークドライブ・リムーバブルでの監視は、実験していない(場面 8 の 8 は任意)。
- ログの文言に依存して見る。文言を変えたら、この手順も直す。
